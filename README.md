# TurtleBot4 Maze Simulations

Gazebo Harmonic based simulations for TurtleBot4, contains following,

| Simulation | Description | Package | Launch File |
|------------|-------------|---------|-------------|
| TurtleBot4 Maze Small | Standard TurtleBot4 in maze world of size 10mx10m | turtlebot4_maze_sim | turtlebot4_maze_small.launch.py |
| TurtleBot4 Maze Large | Standard TurtleBot4 in maze world of size 40mx40m | turtlebot4_maze_sim | turtlebot4_maze_large.launch.py |


## Build

From the root of a ROS 2 Jazzy workspace containing this repository:

```bash
colcon build
```

## Launch

### Start a Gazebo simulation

Start the standard TurtleBot4 model in the small 10 m x 10 m maze world:

```bash
source install/setup.bash
ros2 launch turtlebot4_maze_sim turtlebot4_maze_small.launch.py
```

Start the standard TurtleBot4 model in the large 40 m x 40 m world:

```bash
source install/setup.bash
ros2 launch turtlebot4_maze_sim turtlebot4_maze_large.launch.py
```

The Gazebo GUI is enabled by default. For a headless server-only simulation, use the `gui:=false` argument:

The large world combines three different navigation spaces in a single map:

- a mostly empty open area of about 10 m x 10 m
- a narrow corridor of about 2 m x 10 m
- a dedicated maze section in one part of the map

### Start the control stack

Run the stock TurtleBot4 navigation launches after the Gazebo world is already running. The maze world now publishes standard global TurtleBot topics by default, so no simulation-specific Nav2 wrapper is required.

```bash
source install/setup.bash
ros2 launch turtlebot4_navigation slam.launch.py use_sim_time:=true
```

In a second terminal:

```bash
source install/setup.bash
ros2 launch turtlebot4_navigation nav2.launch.py use_sim_time:=true
```

Optional RViz session:

```bash
source install/setup.bash
rviz2 -d src/turtlebot4_simulations/turtlebot4_maze_sim/config/maze.rviz
```

## Control and telemetry

The simulation accepts `geometry_msgs/msg/TwistStamped` commands on `/cmd_vel`. For example, drive forward at 0.1 m/s; stop the publisher with Ctrl+C to stop the robot:

```bash
ros2 topic pub --rate 10 /cmd_vel geometry_msgs/msg/TwistStamped "{twist: {linear: {x: 0.1}, angular: {z: 0.0}}}"
```

Available ROS topics:

| Data | Topic | Type |
|------|-------|------|
| LiDAR | `/scan` | `sensor_msgs/msg/LaserScan` |
| RGB image | `/camera/image_raw` | `sensor_msgs/msg/Image` |
| Depth image | `/camera/depth/image_raw` | `sensor_msgs/msg/Image` |
| Camera info | `/camera/camera_info` | `sensor_msgs/msg/CameraInfo` |
| Battery | `/battery_state` | `sensor_msgs/msg/BatteryState` |

Battery telemetry is generated by Gazebo Harmonic's `LinearBatteryPlugin` and bridged to ROS. It is a simulated battery model, not a reading from TurtleBot4 hardware.
